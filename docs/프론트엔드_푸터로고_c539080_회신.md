## 1. 결론

- **맞습니다.** 같은 날(11/16) 방식을 바꿨고, c539080은 지금 쓰이지 않는 코드입니다.
- **일부러 남긴 것이 아닙니다.** `frontend` 브랜치에서 빼셔도 됩니다.

## 2. 무슨 일이 있었나

같은 기능("푸터에 CommentEngine 로고, 누르면 서비스 선택 화면으로")을 두 가지 방식으로 만들었습니다.

| | c539080 (먼저) | #33 (나중, 현재 방식) |
|---|---|---|
| 시각 | 11/16 20:04 | 11/16 20:28 |
| 위치 | Finesse `frontend` 브랜치 | MSA 참고용 레포 `chips/tetris/frontend/` |
| 방법 | 이미지 안 React 코드가 `/engine.json`을 받아 푸터에 로고를 그림 | 칩 쪽 Nginx가 `engine-logo.js`를 화면에 끼워 넣음 (`sub_filter`) |
| 이미지 코드 수정 | 필요 (5개 파일) | **불필요** |
| 주소 전달 | `ENGINE_HOME_URL` 환경변수 → `/engine.json` | `engine-logo.js`가 직접 처리 |

#33으로 바꾼 이유는 "이미지(모놀리식과 공용) 코드를 건드리지 않고 MSA에서만 로고를 붙이기 위해서"입니다. #33의 설정 파일 주석에도 *"이미지 코드는 바꾸지 않는다"*고 적혀 있습니다.

## 3. 왜 지금은 쓰이지 않나

```
[MSA]   #33의 default.conf.template이 이미지의 Nginx 설정을 통째로 대체
        → /engine.json 위치 블록이 없음
        → engineHome.ts가 요청해도 로고가 나오지 않음 (로고는 engine-logo.js가 담당)

[모놀리식]  ENGINE_HOME_URL 기본값이 빈 값
        → 로고가 숨겨짐 → 아무 동작도 하지 않음
```

| 환경 | c539080 코드가 하는 일 |
|---|---|
| MSA | 안 쓰임 (Nginx 설정이 대체됨) |
| 모놀리식 | 안 쓰임 (환경변수가 비어 로고 숨김) |

따라서 `main`에 합칠 때 같이 들어가도 효과 없이 코드만 늘어납니다.

## 4. 커밋이 바꾼 파일

5개 파일입니다.

- `frontend/Dockerfile`
- `frontend/nginx/default.conf.template`
- `frontend/src/components/SiteFooter.tsx`
- `frontend/src/i18n/strings.ts`
- `frontend/src/lib/engineHome.ts` (새 파일)

## 5. 함께 정리할 것 (참고용 레포)

`chips/tetris/compose.yml:79`에 아래 줄이 남아 있습니다.

```yaml
- ENGINE_HOME_URL=${TETRIS_ENGINE_HOME_URL:-}   # 푸터 로고 → 서비스 선택 화면
```

#33 이후에는 이 환경변수를 읽는 곳이 없습니다 (c539080 방식에서만 쓰였음). 이 줄과 `.env`의 `TETRIS_ENGINE_HOME_URL` 안내가 필요한지 확인해서 함께 정리하면 좋겠습니다.
